# Groq Free scoped questions and refund guidance

The V02 and V03 full snapshots use one new PostgreSQL seed and one closed
application instance. Runs go through the ordinary HTTP application route.
V25 is the request baseline. Offline comparison normalizes version and
citation IDs from the fresh seed and permits only the narrowed requirement
enum in both requests and the refund guidance in V03. The previous system
instruction for V02 is unchanged.

The runner pins both exact outbound bodies, source bindings, case versions,
the SDK and code hashes before a key is read. Each POST is written to the
attempt ledger before transmission. The plan is Free, with a 1,000-token
completion limit, no reasoning, at least 65 seconds between sends, zero
retries and a stop at the first technical failure. The key is supplied
through standard input to one closed process.

The v3 frozen evaluator checks both transformed cards against their full
case references. The application also checks the scoped questions and the
reviewed bank evidence. Original responses with citation IDs and resolved
cards are stored separately. No operator approval is created by the runner.
