# Проверка переключения LLM-провайдеров

Проверено 13 ноября 2026 года на ветке `codex/configurable-live-providers`,
созданной непосредственно от master `36f175d37aab242d8b33b8352ba323b1019d3d3c`.
Это offline-проверка подключения через настройки, не live-приёмка этапа 4.
Реальных модельных вызовов — **0**; commit, push и внешнее размещение не выполнялись.

## Реализовано

`LLM_PROVIDER`, `LLM_MODEL` и `LLM_API_KEY` выбирают Groq, DeepSeek, OpenAI или
Anthropic без пользовательских правок кода. Первые три используют общий
Responses-адаптер с явными параметрами; Anthropic — native Messages на HTTPX,
API version `2026-10-21`. Новых зависимостей и миграций нет. Старые `OPENAI_*`
действуют только для OpenAI. Groq выбран в образце настроек как кандидат для Free
демо, при этом Live остаётся выключенным, ключ и модель задаются явно.

Инструкции и полный `AssemblyOutput` не изменены. Проверки, snapshots, версии,
CAS, идемпотентность и явное решение оператора остаются общими. В UI и деталях
запуска показаны выбранные провайдер и модель. Денежная стоимость остаётся `null`.
Рецепты и границы настройки — в [live-provider.md](live-provider.md).

In-memory HTTP-тесты проверяют точный endpoint, заголовки, схему, отсутствие
инструментов/повторов/redirects, ошибки 401/403/402/429/400/500, deadline, refusal,

историю, snapshot и повтор ключа. Все ключи в тестах фиктивные.

Независимое review нашло две ошибки обработки повреждённых ответов: потерю
request ID/raw при сбое SDK-разбора и недопустимые для JSONB ID/model/usage.
Обе воспроизведены до исправления. Добавлены 13 транспортных регрессий и четыре
PostgreSQL-регрессии с NUL/непарным surrogate. Теперь сохраняется failed run с
известной диагностикой; небезопасные metadata сохраняются обратимо как текст.
Весь Python-набор после исправлений прошёл повторно.

## Сохранность основного демо

Тесты использовали только новые `proofline-provider-test` и
`proofline-provider-e2e`. Основной проект `proofline` на 8000 не пересоздавался.
До и после совпали количество строк и хеш содержимого всех семи таблиц:
6 обращений, 21 источник, 21 версия текста, 3 запуска, 5 версий разбора,
8 проверок и 2 операторских решения. Готовность основного API подтверждена.
Созданные тестовые контейнеры и отдельный тестовый том удалены.

Первичная инициализация нового Compose-тома заняла больше окна healthcheck
из-за длительной синхронизации файлов PostgreSQL. После завершения штатного initdb
проект стал healthy; проверки прошли без изменения конфигурации БД или проверок.

## Что остаётся открытым

Фактический API-доступ, доступность выбранной модели, принятие полной схемы,
качество на русских кейсах, latency/usage и условия Free Plan не измерены.
Следующая live-приёмка требует отдельного согласования. Для публичного демо
отдельно нужны ограничения запросов, доступ и изоляция посетителей; один локальный
оператор не объявляется готовой многопользовательской средой.
