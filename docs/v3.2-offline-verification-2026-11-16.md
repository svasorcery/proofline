# Диагностика и инструкция v3.2: offline-проверка

16 ноября 2026 года. Изменения в `codex/configurable-live-providers`, без commit,
push, внешних загрузок, чтения реального ключа и новых inference-вызовов.

## Изменения

Responses-адаптер теперь различает Groq HTTP 400 с известным
`json_validate_failed`: это `INVALID_MODEL_OUTPUT`, с сохранением request ID,
HTTP status и `provider_error_stage=output_validation`. Обычный 400 и ошибки
других провайдеров сохраняют прежнюю классификацию.

`provider_error_code`, `provider_error_type`, `provider_error_param` принимают
только строки из закрытых allowlist. Неизвестные значения, вложенные объекты,
массивы, NUL и непарные surrogate не попадают в диагностические идентификаторы.
Message, exception string, полное error body и failed_generation не сохраняются.
Один request на run, отсутствие retries/fallback и идемпотентность сохранены.
Это улучшение классификации и диагностики, а не доказательство устранения
генеративной ошибки провайдера.

В пакет скопировано только утверждённое тело
[кандидата v3.2](proposals/2026-11-16-live-policy-v3.2-candidate.txt), без заголовка
предложения и маркеров. Runtime не читает файл из docs или notes.

- Policy: `proofline-policy-v3.2-candidate-1`.
- Prompt: `proofline-responses-prompt-v2-candidate-1`.
- Schema: прежняя `assembly-output-v1`, без ослабления constraints.

Новые версии и SHA256 различают этот профиль и v3.1 в старых runs. Качество
новой инструкции **не измерено**; новые модельные вызовы не разрешались и не делались.

## Offline Compose: метод и ограничение проверки

Проверялись только новые проекты `proofline-v32-unitpg-20261116` и
`proofline-v32-check-20261116`. Ни один image или пакет из сети не скачивался.

Для Compose использован уже имевшийся локальный runtime image с теми же locked
зависимостями и UI, а актуальный `src` подключён read-only через PYTHONPATH.
Capabilities подтвердили новые v3.2 ID. Это проверка свежего кода и сквозного
процесса на локальном образе; полная пересборка Dockerfile здесь не заявляется.
Wheel/sdist текущего исходного дерева собраны отдельно offline.

На Docker Desktop сеть `internal=true` не публиковала host port: приложение было
healthy, но `NetworkSettings.Ports` оставался пустым. Это проверено отдельно из
контейнера. Для браузерных сценариев временный проект переведён на loopback-порт
8003, с запрещёнными настоящими HTTPX transports в серверном процессе,
LIVE_ENABLED=false и пустыми ключами. Playwright использовал временный proxy,
разрешающий loopback, а внешние запросы направляющий в закрытый локальный адрес.
Основные сети не менялись. Временная конфигурация браузера после работы удалена.

## Проверка исторических данных после смены кода

```sh
python -B -X utf8 scripts/verify_live_archive.py evals/live/v1-groq-2026-11-16
```

Новая команда строго проверяет сохранённые artifact hashes, request SHA из
исторического snapshot/шаблона, prompt/schema SHA, raw/canonical, body hash,
идемпотентные ключи, бюджет и отсутствие решений. Обход пути за пределы архива
отклоняется. Повреждение записи остаётся ошибкой даже при различающемся runtime.

`source_drift` показывает изменения текущего кода относительно записанного
runtime отдельно. Сейчас различаются ожидаемые `live_profile.py` и
`openai_responses.py`. Это не означает порчу архива. Старый verifier сохранён
как исторический инструмент с более сильным требованием того же checkout;
его исходные проверки и старые хеши не переписывались.

Правила `.gitattributes` расширены для `evals/live/**` и `evals/diagnostics/**`:
Git сохраняет их исходные bytes, включая recorded CRLF. Два теста с настоящим
Git clean filter подтвердили проблему до исправления и сохранение bytes после.
Прежние правила frozen baseline/fixtures/contracts сохранены.
