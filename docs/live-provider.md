# Live-анализ через OpenAI Responses API

Адаптер этапа 4 реализован и проверяется без сети через официальный Python SDK.
**Реальных модельных вызовов и live-приёмки ещё не было.** Доступность модели,
совместимость схемы, качество новой инструкции и фактические расходы не измерены.
Replay остаётся рабочим демонстрационным режимом по умолчанию.

## Настроить после согласования live-приёмки

На backend задаются `LIVE_ENABLED=true`, отдельный `OPENAI_API_KEY` и явно выбранный
`OPENAI_MODEL`. Значений модели и ключа по умолчанию нет. Используется только
`https://api.openai.com/v1/responses`; `OPENAI_BASE_URL` не перенаправляет адаптер.
Авторизация ChatGPT/Codex не используется. Не сохраняйте ключ в репозитории,
интерфейсе, shell history или материалах приёмки.

Compose передаёт эти переменные только приложению. После изменения окружения
пересоздайте app выбранного Compose-проекта; запуск контейнера сам по себе модель
не вызывает. Перед каждым live-прогоном согласуйте модель, условия и бюджет.
Историческое `gpt-5.6-sol` из Replay не является настройкой API-модели.

`MODEL_TIMEOUT_SECONDS=90` задаёт общий deadline запроса и сетевые timeout.
`MODEL_MAX_OUTPUT_TOKENS=4096` ограничивает вывод, включая reasoning-токены,
когда они учитываются провайдером. Обе настройки должны быть положительными.
Входные лимиты общие с Replay: текст не обрезается автоматически.

`GET /api/v1/capabilities` не обращается к OpenAI. `live_available=true` означает
только наличие явной конфигурации; `live_access_verified=false` сохраняет отличие
от live-приёмки. Отсутствующий ключ или модель не ломают replay readiness.
Ненастроенный `mode=live` возвращает 503 `LIVE_NOT_CONFIGURED` без создания run.

## Выполнить и проверить результат

В UI явно выберите «Live — новый вызов» и проверьте показанную модель.
HTTP-команда использует тот же маршрут и заголовок идемпотентности:

```json
{"mode": "live", "expected_case_version": 1}
```

`replay_id` для Live запрещён. На новый run выполняется один Responses request:
SDK `max_retries=0`, без повторной генерации, polling, fallback, инструментов,
фонового выполнения и автоматического исправления ответа. HTTP redirects не
выполняются. Повтор того же ключа возвращает прежний run (202 во время выполнения,
200 после завершения). Только новая явная команда с новым ключом создаёт попытку.

Run сохраняет snapshot до запроса. Весь выбранный текст и каталог передаются
в одном JSON-входе; тексты исключённых источников в нём отсутствуют. Политика
считает обращение, контекст, метаданные и документы недоверенными данными.
Эталоны, recorded answers и исследовательский evaluator в запрос не входят.

`providers/live_profile.py` содержит самостоятельную адаптацию неизмеренного
кандидата v3.1 и действующей спецификации, включая раздельные отправку/получение,
безусловное принятие альтернативы и запрет повторного чтения уже выданного
снимка ради нового подтверждения. Это новый профиль
`proofline-policy-v3.1-unmeasured-1`, а не измеренная историческая политика.
Схема строится из `AssemblyOutput` и передаётся как `text.format=json_schema`,
`strict=true`. Полученный JSON всё равно разбирается и проверяется приложением.

Сохраняются запрошенная и возвращённая модель, ID ответа и request ID, если они
получены, версии и SHA256 политики/инструкции/схемы, SHA256 всего тела запроса,
deadline, output limit, latency, raw output, usage и безопасная ошибка.
`prompt_sha256` — хеш текста инструкции; полный вход связан через snapshot и
`request_sha256`. В `raw_output` хранится текст результата, в том числе частичный;
для отказа без текстового результата — JSON выходных элементов с отказом.
При неверной форме SDK-ответа сохраняется диагностический JSON envelope с
`raw_output_format=response-envelope`, а известные ID и usage остаются доступными.
Каноническая карточка и результаты проверок хранятся отдельно.
Если исходный текст содержит символы, недопустимые для PostgreSQL text (NUL или
непарный surrogate), raw сохраняется обратимо как JSON-строка с
`raw_output_encoding=json-string`. Декодирование этой строки восстанавливает
исходный текст; это диагностическое представление, не исправленная карточка.

Usage сохраняется только полученным от API. При его отсутствии, в том числе при
timeout, значение `null`; нулевые расходы не предполагаются. Денежная стоимость
и тариф в этом адаптере всегда `null`: конфигурации датированного тарифа нет.
Текст HTTP-ошибок и исключений не сохраняется и не выводится: он может содержать
секреты или входные данные. Request ID позволяет сопоставить безопасную запись.

| Код run | Причина |
| --- | --- |
| `MODEL_REFUSAL` | Отказ модели |
| `MODEL_OUTPUT_INCOMPLETE` | Неполный ответ, включая output limit |
| `INVALID_MODEL_OUTPUT` | Пустой, невалидный JSON или нарушение контракта |
| `MODEL_TIMEOUT` | Сетевой timeout либо общий deadline |
| `PROVIDER_ACCESS_DENIED` | HTTP 401/403 |
| `PROVIDER_RATE_LIMITED` | HTTP 429, включая исчерпанную квоту |
| `PROVIDER_REQUEST_REJECTED` | HTTP 400/404/422: модель, схема или параметры |
| `PROVIDER_ERROR` | Связь, серверная или другая ошибка провайдера |

Failed run не создаёт новую карточку и не переключает режим. Разобранный ответ
с ошибками доказательств создаёт succeeded run и заблокированную карточку.
Поздний результат остаётся кандидатом при изменившейся Case.version. Прерванный
владелец и CAS обрабатываются тем же механизмом, что в Replay. Успешная проверка
всегда оставляет решение человеку: автоматического подтверждения нет.

## Отдельная live-приёмка

1. Согласовать API-доступ, конкретную модель, число запросов и допустимые расходы.
   Включить в бюджет проверку доступности/совместимости и ошибки; не начинать
   пробные вызовы до согласования.
2. Зафиксировать профиль, версию SDK/lockfile и параметры. На выбранном доступе
   проверить Structured Outputs и известные проблемные условия V02/V04, затем
   согласованный набор. Каждый новый run расходует максимум один request;
   повтор ключа не считается новой попыткой.
3. Сохранить новые результаты в отдельном версионированном каталоге evals, с
   моделью, условиями, usage, неизвестными величинами и ручным review. Отдельно
   оценить значения фактов, достаточность доказательств, полноту хронологии и
   следующий шаг. Не переносить метрику v3 7/9 на новую инструкцию.

Детерминированные тесты не доказывают качество модели, её доступность на аккаунте
или принятие схемы реальным API. Frozen baseline и записанные ответы неизменны.

Основания: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[официальный Python SDK: retries, timeouts и ошибки](https://developers.openai.com/api/reference/python),
[Responses create](https://developers.openai.com/api/reference/python/resources/responses/methods/create).
