# Запустить гостевое демо на закрытом стенде

Гостевой режим открывает каждому браузеру свою копию шести синтетических обращений. Запуски Replay, правки карточек, версии источников и решения доступны только в том рабочем пространстве, где они созданы. Смена или потеря cookie открывает новое пространство, а прежние записи остаются в базе.

Используйте отдельный Compose-проект с собственной БД. В PowerShell из корня проекта выполните:

```powershell
$env:GUEST_MODE = 'true'
$env:LIVE_ENABLED = 'false'
$env:PROOFLINE_PORT = '8001'
$env:APP_ORIGIN = 'http://127.0.0.1:8001'
docker compose -p proofline-guests -f infrastructure/compose.yml up -d --wait db
docker compose -p proofline-guests -f infrastructure/compose.yml run --build --rm app migrate
docker compose -p proofline-guests -f infrastructure/compose.yml up -d --wait app
```

Откройте `http://127.0.0.1:8001` в двух независимых профилях браузера. Создайте разбор Replay и новую правку в первом профиле. Во втором открывается собственная очередь и прямые ссылки первого профиля возвращают 404. Чтобы остановить этот стенд и сохранить гостевую историю, выполните `docker compose -p proofline-guests -f infrastructure/compose.yml stop` в той же сессии.

Сервер создаёт сессию по `POST /api/v1/guest-session` с разрешённым `Origin` и выдаёт cookie `proofline_guest` с `HttpOnly` и `SameSite=Strict`. При HTTPS в `APP_ORIGIN` добавляется `Secure`. В базе хранится хеш токена. Без действующей cookie операции с рабочим пространством возвращают `401 GUEST_SESSION_REQUIRED`. Интерфейс открывает сессию при первом таком ответе на чтение и повторяет само чтение. Команды изменения отправляются по явному действию. Web Locks координирует открытие новой сессии между вкладками. В браузерах без этой возможности первый одновременный вход в нескольких вкладках может создать несколько пространств.

Replay проверяет вход гостевой копии по оригиналу записи и сохраняет исходный ответ модели отдельно от карточки с ID гостевого обращения.

## Live с общим лимитом стенда

На закрытом стенде с `GUEST_MODE=true` гостевой Live включается явно. Он принимает входы, которые совпадают с одним из сохранённых синтетических условий. Изменения текста, фактов или источников требуют заново выбрать совместимый кейс.

Перед включением проверьте тариф Free и лимиты организации в консоли Groq. Используйте отдельный ключ для стенда и задайте `LLM_API_KEY` в закрытом окружении сервера. API приложения получает ключ из конфигурации. Храните его вне Git и интерфейса. [Лимиты Groq](https://console.groq.com/docs/rate-limits).

В той же PowerShell-сессии обновите переменные и пересоздайте контейнер API для гостевого стенда:

```powershell
$env:LIVE_ENABLED = 'true'
$env:LLM_PROVIDER = 'groq'
$env:LLM_MODEL = 'openai/gpt-oss-20b'
$env:GROQ_REASONING_EFFORT = 'low'
$env:MODEL_MAX_OUTPUT_TOKENS = '1000'
docker compose -p proofline-guests -f infrastructure/compose.yml up -d --force-recreate app
```

| Ограничение | Правило стенда |
| --- | --- |
| Гостевой бюджет | До 3 попыток на сессию за скользящие 24 часа. |
| Общий бюджет | До 20 попыток за скользящие 24 часа. Резерв 8 000 токенов на попытку даёт 160 000 токенов зарезервированного бюджета. |
| Одновременные вызовы | Один новый вызов на весь стенд. Пауза 65 секунд от завершения предыдущей попытки. |

PostgreSQL резервирует попытку до обращения к провайдеру в одной транзакции с записью запуска. Ошибка провайдера и прерванный запуск расходуют резерв. Повтор того же запроса с тем же ключом идемпотентности возвращает существующий запуск. Смена гостевой cookie создаёт новую сессию и сохраняет расход общего бюджета. Резерв учитывается отдельно от фактического числа токенов в ответе. Groq применяет свои лимиты ко всей организации. Для стенда используется один процесс API и выделенная база.

При отказе по лимиту API возвращает `429 GUEST_LIVE_RATE_LIMITED`, причину и `Retry-After` в секундах. Интерфейс объясняет причину и предлагает вручную выбрать Replay, если запись для входа доступна.

При стандартной конфигурации для гостевой копии полного V06 приложение использует инструкцию v55 и подставляет дословные цитаты из версий источников этого гостя. Если в хронологии есть только подтверждённая отмена, а модель уже сослалась на проверенную строку снятия резерва в факте об оплате, приложение добавляет событие по этой строке. Остальные гостевые кейсы используют v3.2. [Отдельная live-приёмка](live-provider.md#отдельная-live-приёмка).
