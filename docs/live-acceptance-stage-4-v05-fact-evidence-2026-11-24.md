# Контроль V05 с отдельным доказательством получения отказа

**Groq вернул HTTP 200. Карточка собрана, одобрение заблокировано.**
Модель устранила две ошибки из v31. Каждый ID в списке доказательств
указан один раз, а факт о получении отказа до отмены опирается на
текст отказа, время получения поставщиком и операцию отмены. Однако
отправка уведомления на следующий день снова появилась в хронологии
как вторая отмена. Этап 4 остаётся открыт.
[Результат и архив v32](../evals/live/v32-groq-qwen-v05-fact-evidence-2026-11-24/manifest.json).

На контрольном стенде отправлен один V05 на `qwen/qwen3.8-27b` в
Groq Free, `reasoning_effort=none`, потолок 1 000 выходных токенов, бюджет
$0, повторов ноль. Groq сообщил 3 920 входных и 453 выходных токена.
С v31 совпали источники, ID цитат, схема и параметры. Изменилась только
тестовая инструкция V05. Остальные пять запросов сохранены.
[Предзапусковая сверка](../evals/live/v32-groq-qwen-v05-fact-evidence-2026-11-24/preflight.json),
[сверка карточки](../evals/live/v32-groq-qwen-v05-fact-evidence-2026-11-24/full-V05/review.json).

Следующий вариант проверен локально в Ajv. Для события
`supplier_cancelled` схема V05 разрешает только время из проверенной
операции поставщика. Такая схема отклонила и лишнюю вторую отмену в
ответе v32, и замену времени правильной отмены на время уведомления.
Копия с тремя подтверждёнными событиями прошла схему и эталон.
Это офлайн-прототип. В живом запросе он пока не используется.
[Проверка схемы на сохранённом ответе](../evals/live/v32-groq-qwen-v05-fact-evidence-2026-11-24/offline-V05-cancellation-time-schema.json).

Прошли 470 тестов Python с PostgreSQL, 21 тест замороженного набора,
Ruff, mypy, сверка опубликованной схемы и операторский Replay walkthrough.
Стенд остановлен. Сверены 630 защищённых файлов, состояния 42 прежних
контейнеров и содержимое тома v31.
