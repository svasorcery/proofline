# Этап 4 остаётся открытым после V01

В последней серии v38 на закрытом стенде Groq отклонил ответ на V01 с HTTP 400 `json_validate_failed`. Запрос совпадает побайтно с V01 из v29 и v34, где Groq вернул проходящие карточки. Локальный Ajv пропускает ответ v34 на этой же схеме. В журнале v38 видны 3 456 входных и 3 выходных токена. Отклонённый текст и поле схемы недоступны. После ошибки стенд остановлен. V02–V06 в этой серии не отправлялись. [Архив серии](../evals/live/v38-groq-qwen-stage4-acceptance-2026-11-24/manifest.json), [наблюдение из журнала](../evals/live/v38-groq-qwen-stage4-acceptance-2026-11-24/provider-console-observation.json).

## Что изменилось в приложении

Groq и DeepSeek используют клиент с явно заданным набором HTTP-заголовков. Тесты на подставном окружении проверяют, что OpenAI-специфичные заголовки и подставной `Authorization` не попадают в запросы к этим провайдерам. Модель и провайдер по-прежнему задаются настройками. [Клиент совместимости](../src/proofline/providers/compatible_sdk.py), [тесты адаптеров](../tests/unit/test_live_providers.py).

В тестовом профиле V03 и V05 приложение связывает уже выбранные моделью цитаты по проверенным версиям источников. Для V03 это банковская трасса, выбранная в событии зачисления. Для V05 это отметка о получении, текст сообщения и тип существующего события. Схема V05 требует минимум два события при совпадении обеих проверенных записей. Приложение сохраняет исходный ответ отдельно от карточки. Выбор фактов, времени событий и ID цитат остаётся в ответе модели. Преобразование требует совпадения источника и нужной цитаты в ответе.

Более сложная схема с отдельными полями подтверждений возврата прошла локальный Ajv, а Groq отклонил её до генерации в v35. В финальном профиле сохранена уже принятая провайдером форма ответа V03. [Диагностика v35](../evals/live/v35-groq-qwen-typed-evidence-control-2026-11-24/provider-console-observation.json).

На тарифе Free отправлено пять запросов v35–v38, без автоматических повторов, с бюджетом $0. С учётом журнала для двух отказов использовано 15 974 токена. Стенды приёмки остановлены. Основное демо было остановлено к началу проверки и сохранило это состояние. Сверены 768 файлов, состояния 48 прежних контейнеров и содержимое тома v34. Проверены все 38 live-архивов, включая 648 контрольных сумм артефактов. Прошли 472 теста Python с PostgreSQL, 43 теста интерфейса, 11 сценариев Chromium, 21 тест замороженной базы, проверки Ruff, mypy, TypeScript и канонической схемы. Отдельный Replay walkthrough сохранил исходную заблокированную карточку, операторскую правку и явное решение без вызовов модели. [Сохранность](../evals/live/v38-groq-qwen-stage4-acceptance-2026-11-24/preservation.json).

## Саморевью и следующий шаг

Proofline уже решает исходную задачу оператора на учебных данных. Для спорного факта можно открыть точную цитату, внести правку отдельной версией и сохранить решение. Ошибка Groq сохраняется отдельным запуском, поэтому историю можно проверить после отказа. Границы между источником, ответом модели и решением человека выдерживают проверки с настоящей БД, включая гонки.

Надёжность live для посетителей пока не доказана. Эталонные кейсы использовались при разработке, а правила для двух из них привязаны к размеченным версиям источников. Они подтверждают поведение на этих данных. Для вывода о новых обращениях нужна отдельная подборка с другими и конфликтующими источниками.

Следующий кандидат для контроля V01 — `openai/gpt-oss-20b` на Groq Free с `reasoning_effort=low`. Groq указывает для этой модели поддержку строгой схемы и бесплатную квоту. Сравнение должно сохранить вход, инструкцию, схему и рубрику V01 на отдельном профиле. Один вызов покажет совместимость именно с этим запросом. Для принятия этапа затем потребуется одна цельная серия V01–V06. Qwen тоже указан в документации строгого режима. По доступному журналу точный механизм отказа v38 установить не удалось. [Строгая схема](https://console.groq.com/docs/structured-outputs#supported-models), [уровни reasoning](https://console.groq.com/docs/reasoning), [квоты](https://console.groq.com/docs/rate-limits).

Публичному демо дополнительно нужны отдельная история для каждого посетителя, серверный лимит запросов и токенов до отправки, защита от параллельных вызовов и явное сообщение при отказе или исчерпании Groq Free. Перед вводом своих данных нужно определить, какие тексты можно отправлять провайдеру. Упаковка и публикация остаются отдельной работой. [Ревью границ публичного запуска](solution-review-2026-11-18.md).
