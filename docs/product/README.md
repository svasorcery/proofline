# Продуктовая история Proofline

[Читать документ](proofline.ru.md) · [открыть HTML локально](proofline.ru.html) · [карта SVG](assets/proofline-map.svg) · [карта PNG](assets/proofline-map.png)

`proofline.ru.md` – единственный редактируемый текст. Он описывает конечный вид проекта по [спецификации](../spec.md), а не статус текущего релиза. Актуальные результаты проверок остаются в [README проекта](../../README.md) и технической документации.

`proofline.ru.html` – версия для чтения с оглавлением, адаптивной вёрсткой и встроенными схемами. Её можно передать одним файлом и открыть без сервера и интернета. Ссылки на технические документы ведут в GitHub. На самом GitHub HTML показывается как код: для чтения скачайте файл и откройте в браузере.

В `assets/` три схемы в SVG и PNG: устройство продукта, исправление условного согласия, история документов и решений. Текст внутри схем и оформление находятся в [скрипте сборки](../../scripts/build_product_story.mjs). Стиль продолжает продуктовый рассказ [Travel](https://github.com/svasorcery/travel-agency/blob/dev/docs/product/travel.ru.md).

## Обновление

Из корня репозитория, с Node.js 22.12+:

```sh
node scripts/build_product_story.mjs
```

Команда пересобирает SVG, HTML и `publication.json` без сторонних пакетов и сетевых запросов. Манифест содержит заголовок, описание и SHA256 текста и трёх SVG для сборки блога. Файлы сохраняются в UTF-8 с переносами LF; локальная `.gitattributes` закрепляет этот формат при checkout. Обработчик Markdown поддерживает используемые здесь заголовки, абзацы, одну цитату, выделение, ссылки и изображения. Неподдерживаемые блочные конструкции завершают сборку ошибкой.

Для экспорта PNG используется Playwright из frontend и локальный Chromium:

```sh
npm --prefix frontend ci
npm --prefix frontend exec -- playwright install chromium
node scripts/build_product_story.mjs --png
```

После изменения текста или схем пересоберите производные файлы. Проверьте ссылки, оглавление, читаемость схем и отсутствие горизонтальной прокрутки на узком экране. При добавлении Markdown-конструкций отдельно проверьте, что локальная HTML-версия отображает их правильно.

## Страница в блоге

Путь страницы – `/projects/proofline/`. Блог получает Markdown и SVG из опубликованной версии этого репозитория при сборке. Вторая редактируемая копия текста в блоге не нужна. Обновление производных HTML/PNG здесь обслуживает локальное чтение и просмотр изображений; блог использует Markdown/SVG.

Публикуемый источник: `svasorcery/proofline`, ветка `master`, файл `docs/product/proofline.ru.md`. Сначала исходник и схемы должны появиться в опубликованной ветке, затем можно активировать источник в настройках блога. Настройка загрузки, меню и автообновления принадлежит репозиторию блога. Его наличие не требуется для запуска или понимания Proofline.
