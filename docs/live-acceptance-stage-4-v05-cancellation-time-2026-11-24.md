Тестовая схема V05 при совпадении проверенной отметки об отмене разрешает
для `supplier_cancelled` её подтверждённое время и роль `occurred`.
Строка об отправке уведомления больше не превращается во вторую отмену
ни в контрольном, ни в приёмочном ответе. В v33 и v34 запрос V05 совпал
целиком. Остальные пять запросов совпали с v29, включая V03, который в
v29 прошёл. Это показывает разницу двух ответов на один и тот же запрос.
[Офлайн-сверка](../evals/live/v34-groq-qwen-stage4-acceptance-2026-11-24/offline-cancellation-verification.json).

На сохранённых ответах проверены следующие варианты без вызова модели.

- **V03.** Добавление в копию только строки трассы из выписки вернуло
  полный проход эталона. Локальная схема с обязательными полями для
  ссылок допускает подтверждение общей трассой или прямой ссылкой на
  выписку. Вариант с недостающей связкой отклоняется.
  [Проверка V03](../evals/live/v34-groq-qwen-stage4-acceptance-2026-11-24/offline-V03-missing-bank-trace-check.json).
- **V05.** На копии исправлены только два типа событий. Исходные
  времена и цитаты достаточны. Локальный вариант схемы для снимка с
  одной проверенной отметкой о получении отказа связывает отправку с
  ролью `sent`, а получение отказа — с `received`. Он отклоняет обе
  ошибки из v34.
  [Проверка карточки](../evals/live/v34-groq-qwen-stage4-acceptance-2026-11-24/offline-V05-event-label-check.json),
  [прототип схемы](../evals/live/v34-groq-qwen-stage4-acceptance-2026-11-24/offline-V05-typed-event-schema.json).
