# Безопасная диагностика полей ответа V04

В Groq Chat при `json_validate_failed` приложение теперь сравнивает поля верхнего уровня отклонённого JSON-объекта с отправленной схемой. В записи появляются только имена пропущенных обязательных полей из схемы и число лишних полей. Текст ответа, его значения и имена неизвестных полей остаются за пределами записи. Это проверено на имитации отказа с закрытыми значениями и в PostgreSQL-тесте сохранения результата и идемпотентности. [Офлайн-проверка](../evals/live/v49-groq-gpt-oss-20b-v04-field-diagnostic-2026-11-25/offline-v04-field-diagnostics.json).

В v49 отправлено то же тело запроса V04, что в v48. Groq снова вернул HTTP 400 `json_validate_failed`. В v48 было зафиксировано несовпадение набора полей. В v49 обязательные поля присутствовали, лишних — ноль. Точное нарушение в v49 по этим данным установить нельзя. Офлайн Ajv отклоняет ответы с таким же набором полей верхнего уровня при разных вложенных ошибках.
