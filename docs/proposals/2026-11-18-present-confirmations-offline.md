# Как убрать из вопросов уже приложенный ответ

Офлайн-проверка 18 ноября. В V04 из копии карточки убран запрос оригинала
ответа клиента. Остались два нужных подтверждения: тихий номер и окна во двор.
В V01 письмо остаётся доступным для запроса по прежнему адресу.

| Кейс | Что есть в обращении | Результат |
| --- | --- | --- |
| V04 | В приложенной записи есть текст условного ответа клиента | Убрали просьбу прислать оригинал. Оба условия о номере сохранены. |
| V01 без оригинала | Журнал подтверждает получение и указывает адрес архива. Самого текста письма в снимке нет | Сохранён запрос оригинала по адресу `1618ae5e5b894145`. |

Для V04 вручную проверен фрагмент с текстом ответа. Он связан с конкретным
обращением, источником, версией и хешем текста. Из допустимых вопросов для
этого снимка убран `original_acceptance_reply`. Название источника, запись
о получении и адрес архива сами по себе вопрос не снимают.

В локальной проверке временная схема V04 отклоняет сохранённый ответ с лишним
вопросом и принимает копию с двумя оставшимися подтверждениями. На V01 тело
запроса осталось эквивалентно прежнему, а ответ с запросом письма принят.
Обе карточки прошли действующий валидатор. Если источник исключён, не совпала
версия, неверен хеш или фрагмент отсутствует, вопрос сохраняется. Если удаление
оставило бы пустой список, прототип останавливает преобразование для отдельной
проверки готовности карточки.

Модельных вызовов — 0. Рабочая v3.2, схема приложения, демо, исходные ответы,
история и архивы сохранены. Эта проверка подтверждает работу правила на
подготовленных примерах. Смысловую связь между вопросом и фрагментом должен
подтверждать доверенный человек или структурированный источник данных.

Запуск с имеющимися локальными зависимостями:

```sh
uv run --locked --offline python scripts/prototype_present_confirmations.py
```

Правило подключено только к отдельному профилю `v3.3-confirmations-test`.
Офлайн SDK подтвердил, что в запросе V04 меняется только список возможных
вопросов, а тело запроса V01 совпадает с архивом целиком. На отдельной
PostgreSQL проверены создание карточки с двумя нужными вопросами и сохранение
ошибочного исходного ответа без карточки.
[Настройка профиля](../live-provider.md#проверка-уже-приложенного-оригинала-ответа).

Следующий шаг — отдельно согласовать один живой V04 на Qwen `medium` в этом
профиле с бюджетом $0. Перед запуском нужно сверить отметку с текущей версией
источника. Критерии остаются прежними: один запрошенный факт, три события
с достаточными цитатами и ровно два нужных подтверждения.
