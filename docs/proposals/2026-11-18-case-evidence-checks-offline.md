# Проверка вопросов и доказательств на сохранённых карточках

На двух карточках v25 действующий валидатор пропустил ошибки, которые
обнаружила сверка с эталоном. Офлайн-прототип воспроизвёл обе ошибки.
Все шесть ранее принятых карточек V01–V06 прошли новые проверки.

| Кейс | Что ловит прототип | Что проходит |
| --- | --- | --- |
| V02 | Вопросы про тихий номер и окна во двор выходят за рамки запрошенных фактов об отказе и отмене. | Исходное сообщение и подтверждение доставки относятся к отказу. Запрос письма в V01 и оба вопроса про номер в V04 сохраняются. |
| V03 | В карточке с зачисленным возвратом не хватает связующего доказательства и трёх событий — списания, запуска возврата и зачисления. | Подтверждение зачисления с общей трассой в двух источниках либо с прямой ссылкой журнала на приложенную выписку. Каждое из трёх событий имеет свою цитату об операции. |

У V02 соответствие проверяется по типу запрошенного факта. Это закрывает
перенос вопросов между темами. Внутри одной темы пригодность конкретного
вопроса по-прежнему зависит от содержания обращения и приложенных источников.

У V03 доказательства факта и хронология проверены отдельно. Цитата трассы
из выписки исправляет доказательства факта, а пустая хронология продолжает
давать три замечания. В обратном контроле вся хронология восстановлена,
а замечание по связующему доказательству остаётся. Проверки используют
предварительно разобранные строки двух выбранных источников с точными
SHA256 текста. Ссылка должна вести на фактический адрес выписки. Одной
цитаты с правильным временем без признака нужной операции недостаточно.
Изменившийся банковский источник требует новой сверки для подтверждения
зачисления. При отсутствующей выписке прототип пропускает карточку, которая
оставляет статус неподтверждённым и запрашивает документ.

Итого 17 офлайн-контролей, ноль модельных вызовов. В скрипте проверяется
содержимое исходных карточек, синтетические варианты создаются в памяти.
Распознавание банковских операций на новых форматах документов здесь
не измерялось.
[Скрипт](../../scripts/prototype_case_evidence_checks.py),
[V02 и V03 из v25](../live-acceptance-stage-4-qwen-none-2026-11-18.md),
[ранее принятые шесть условий](../live-acceptance-stage-4-2026-11-18.md).

```sh
uv run --locked --offline python scripts/prototype_case_evidence_checks.py
```

## Подключение

Правила включены по отдельному параметру в `v3.3-citation-ids-test`.
Один и тот же список допустимых подтверждений используется в строгой схеме
запроса и при проверке сохранённых правок. Для V03 проверка обязательных
событий дополнена требованием цитировать нужную операцию и связь документов.
Интеграционный тест подставляет ответы v25 через HTTP-заглушку и проверяет
обычный путь сохранения на PostgreSQL. В V02 сохраняются лишние вопросы
модели с блокирующими замечаниями. В V03 отдельно видны пропуск связи
документов и неполная хронология. Попытка одобрить каждую из этих карточек
возвращает `VALIDATION_BLOCKED`. Контроли на ранее принятых V02 и V03
доходят до оператора, а режим с выключенным параметром воспроизводит
прежнюю обработку v25. Модельных вызовов при подключении не было.
Отдельная проверка отклоняет второе «зачисление» со временем запуска
возврата. При исключённой выписке карточка может запросить её, а запись
о состоявшемся зачислении требует сверенных доказательств.
При проверенном приложенном ответе V04 повторный запрос оригинала
блокирует и вручную отредактированную карточку.

[интеграционный тест](../../tests/postgres/test_case_evidence_profile.py).
