## Конфигурация и воспроизведение

Профиль зафиксировал `qwen/qwen3.8-27b`, `medium`, 3 072 токена вывода,
90 секунд и `strict=true` в Chat Completions. V01 прошёл с исключённым
оригиналом ответа клиента, V02–V06 использовали полные снимки. Допустимый
непрочитанный источник и привязанная разметка влияют на инструкцию только
своего кейса. Разметка человекочитаема и привязана к тексту источника.
Live-приёмка проверяет эти синтетические сценарии с подготовленной разметкой.
[Профиль](../fixtures/live/groq-stage4-profile.json),
[точные настройки и SHA256](../evals/live/v24-groq-stage4-single-profile-2026-11-18/preflight.json).

На свежей отдельной БД нужно применить миграции и seed, затем исключить у V01
источник `f9a88d5b726a4d4b` через обычный API. Следующая команда читает
снимки из `DATABASE_URL`, сверяет вход и связывает разметку с новыми ID
версий. Результат — JSON с полями `Settings`, без ключа.

```sh
uv run --locked python -m proofline.providers.groq_stage4_profile
```

Перед сетевым запуском испытательный код дополнительно сверяет SHA256
инструкции каждого кейса, активную схему и все поля подготовленного запроса.
Изменение версии кейса после сверки останавливает команду. На новом seed
ID версий и цитат могут отличаться. Архив хранит точные запросы и снимки
для состоявшихся попыток.
[Методика и исходник запуска](../evals/live/v24-groq-stage4-single-profile-2026-11-18/METHOD.md).

Groq и DeepSeek используют отдельные заголовки авторизации и больше не
наследуют `OPENAI_CUSTOM_HEADERS`, `OPENAI_ORG_ID` и `OPENAI_PROJECT_ID`.
Проверка в памяти покрыла обе сетевые ветки. Прошли 452 теста Python с
PostgreSQL, 21 тест замороженного набора, 43 теста интерфейса, 11 сценариев
Chromium и Replay walkthrough. Также прошли Ruff, mypy, сверка схемы и
типов API, сборка пакета и UI. Сверены 442 защищённых файла, состояния
34 прежних контейнеров и содержимое 24 остановленных томов. Закрытый
экземпляр остановлен, в его БД три анализа, две карточки и ноль решений.
[Сохранность](../evals/live/v24-groq-stage4-single-profile-2026-11-18/preservation.json),
[состояние стенда](../evals/live/v24-groq-stage4-single-profile-2026-11-18/application-after-stop.json).

## Следующий контроль

Во всех шести ранее принятых записях `medium` использовал по 1 024
reasoning-токена, а сам JSON занимал 280–473 токена. При отдельном лимите
1 000 на вывод первая проверка кандидата имеет смысл с явным
`reasoning_effort=none` и пределом вывода 1 000. Настройку следует
добавить в конфигурацию тестового профиля, затем проверить V02 на полноту
хронологии и V03 на фактическое принятие провайдером и качество карточки.
Проход этих двух случаев даст основание для повторной приёмки всех шести.
[Поддерживаемые настройки Qwen](https://console.groq.com/docs/reasoning#options-for-reasoning-effort-qwen-3-8-27b).
